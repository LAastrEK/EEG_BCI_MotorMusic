# SSVEP: коридоры допуска и фон

## Калибровка второго уровня

F5 в NeuroPiano и команда `2001` сохраняют первый режим. F6 в NeuroPiano
или PolyHub запускает второй через новую команду существующего канала:
`UserEvent`, `State=1`, `Value0=2006`, `Value1=0`.
На вкладке SSVEP Model кнопки Calbr1/Calbr2 запускают соответствующий этап;
во время работы подписи меняются на Stop1/Stop2. Обе кнопки останова используют
существующую команду `2002`. Подписи обновляются по ответам NeuroPiano,
включая запуск через F5/F6 и останов через Escape. В rtbSsvepStatus выводятся
Calibration 1/2 started, stopped или completed. Это служебные State-события
с кодами существующих команд `2001`/`2006`, без новых маркеров эпох.
Используйте обновлённые проекты вместе. Для проверки ЭОГ нужна подключённая
ЭЭГ; загруженная модель и Use не требуются. Escape/команда `2002` останавливают
калибровку, F5 и F6 взаимно переключают режимы.

Настройки в `NeuroPiano.json`: `CovertCalibrationStartMidiNote` — стартовая
«до» из видимых клавиш по умолчанию, `CovertCalibrationRepetitionsPerTarget`
— 10, `CovertCalibrationNeutralDurationMs` — 2500. Настроенная стартовая нота
должна быть видимой. Остальные длительности берутся из существующих настроек.
Серая стартовая клавиша не мерцает и звучит в начале попытки; семь остальных
мерцают. В каждом круге предъявляются все семь направленных пар от стартовой
клавиши в случайном порядке. Сначала записывается нейтральная эпоха, затем
Cue, Settling и целевая эпоха. После принятой целевой эпохи боковая клавиша
становится серой и звучит, стартовая снова мерцает. Следующая попытка снова
начинается с серой звучащей стартовой клавиши.

Проверка использует существующий профиль Covert Attention. Флажок HEOG
включает сравнение абсолютной амплитуды дифференциального выхода с вручную
заданным порогом в мкВ. Нейтральная эпоха проверяется целиком. Целевая проверка
начинается с исчезновения Cue и включает Settling до END. Превышение только
во время Cue не отклоняет цель; сохраняющийся после Cue сдвиг глаз отклоняет.
VEOG следует своему флажку и порогу этого профиля. При обоих выключенных
флажках режекция отключена, калибровка продолжается. Каналы берутся из полного
потока по выходным именам HEOG/VEOG. Изменение Covert Attention действует
со следующей попытки; профиль Gaze Selection первого уровня остаётся отдельным.

На END PolyHub дожидается ЭОГ и отправляет `2007`, State 0, с точным QPC
этого END и флагами в Value1: 0 — принято, 1 — VEOG, 2 — HEOG,
4 — отсутствующие/некорректные значения ЭОГ в общей проверке данных.
Промежутки между блоками, номера Sequence, изменение частоты и неполное
покрытие интервала не являются причинами режекции. Проверяются полученные
отсчёты внутри интервала. Если CueOff отсутствует, проверка начинается со START.
При режекции отправляется прежнее событие `2005` для звука, попытка повторяется
после InterTrial и не увеличивает число принятых повторов. Команды нот первого
уровня в этом режиме не выдаются.

Маркерами в PHS остаются только исходные START/END: нейтральный класс
`1300` и целевая клавиша `1300 + targetIndex + 1` (1301…1308).
Индексы 0..7 относятся к видимым белым клавишам, диагональные пары не
используются. Частота пары сохраняется в Value1 START/END в мГц.
CueOn не отправляет событие. Исчезновение Cue передаётся существующим
служебным типом State: Code 102, State 1, Value0 — класс пары, Value1 — 0.
Его время сохраняется для проверки ЭОГ при открытии записи, но не является
маркером или эпохой и не рисуется при записи, предпросмотре и проигрывании.
Формат записей PHS сохранён. Запуск/остановка калибровки используют State,
Value0 2006, Value1 MIDI стартовой ноты/0 и в файл не записываются.
State остаётся 1, поскольку сам сервис NeuroPiano продолжает работать.
Кодов Cue нет. Событие 2005 при режекции второго уровня отправляется только
в NeuroPiano для звука; дополнительная линия-маркер в запись не добавляется.

При открытии записи, просмотре эпох, спектров и проигрывании второго режима
режекция проверяется по Covert Attention, включая Settling до START.
Отклонённые эпохи бледнее, отмечены Rejected, статус показывает их количество.
Это предъявление и запись для второго уровня; обучение и распознавание его
модели будут реализованы отдельно. Обучение первого уровня по `1200..1208`
сохраняется.

RESS и shrinkage LDA для целевых нот сохранены. Все восемь нот используют весь
вектор из 16 признаков: восемь RESS-фильтров с двумя гармониками на класс.
Двойного последовательного подтверждения больше нет.

## Калибровочная запись

PolyHub обучает ноты по классам `1201..1208`. Эпохи `1200` из той же записи
используются только как отрицательные примеры. Частота фона — `0`.
Остальные события, включая MIDI-обратную связь, не становятся классами нот.
Неразмеченные участки и дополнительные файлы ЭЭГ в обучение не входят.

Для новой калибровки в `NeuroPiano.json` установите:

```json
"SSVEPCalibrationStimulusMode": 1
```

Это режим одновременного мерцания всех восьми клавиш. Он соответствует игре.
Фон записывается после каждой ноты с фиксацией на одном из шести прямоугольников;
при фоновых Cue, Settling и Stimulus все клавиши мерцают также и в режиме `0`.
Метки ограничивают только Stimulus; Cue и Settling не включаются в обучение.
Длительности целевой и фоновой Stimulus должны быть не короче окна анализа (1 с).

Калибровка на воде проходит тем же путём, без проверки «это вода», блокировки
модели по качеству сигнала или специального тестового режима.

## Математика принятия

Для каждой целевой эпохи сохраняется средний 16-мерный вектор. Коридор ноты —
объединение окрестностей этих калибровочных образцов. Расстояние Махаланобиса
использует полную общую ковариацию всех 16 признаков, с регуляризацией к диагонали
0.5. Сохраняются дисперсии и половина внедиагональной ковариации; признаки не
отбрасываются. Это отдельная метрика допуска, веса существующего LDA не меняются.

Базовый квадрат радиуса равен большему из двух значений: максимального расстояния
целевых обучающих окон до собственных образцов и 95-го процентиля расстояний до
образцов при исключении всей собственной эпохи. Для одной целевой эпохи на класс
используются расстояния до её среднего. Эти расчёты идут в обученном RESS-пространстве;
они не являются независимой проверкой всей модели.

Фоновые эпохи также сохраняются отдельными 16-мерными образцами. Общая копилка
сохраняет разнообразие шести позиций: весь фон не сводится к одному среднему.
Для ноты и фона рассчитывается средняя гауссова плотность вокруг их образцов с той
же метрикой. В отношении плотностей общий нормировочный множитель сокращается.
Усреднение, а не сумма, исключает искусственный перевес фона из-за числа эпох.

Порог логарифма отношения плотностей ноты и фона выбирается отдельно для каждой
ноты по максимальному фоновому отрицательному примеру (не ниже нуля). При оценке
каждой фоновой эпохи её собственный образец исключается из фоновой плотности,
если имеются другие эпохи. Фон не получает коридора принятия или выходного класса.

Одно окно даёт ноту, если одновременно:

1. LDA предпочитает её всем остальным нотам.
2. Вектор находится внутри её целевого коридора.
3. Плотность её образцов выше плотности образцов остальных нот.
4. Превосходство над фоном превышает рассчитанный порог и заданную поправку.

Иначе результат — `None`. В этом состоянии не отправляются ни Play, ни Release,
буфер анализа не сбрасывается. Уже выбранная серая клавиша остаётся в прежнем
режиме; её мерцание не включается автоматически.

Если в записи нет фоновых эпох `1200`, обучение и сохранение всё равно завершаются,
RESS и признаки доступны для просмотра. Сравнение с фоном отсутствует, поэтому
выход нот не разрешается. Модели версии 1 также загружаются для просмотра, но
не порождают безусловных нот. Для полноценного применения нужна новая калибровка
с фоновыми метками. В анализе отсутствие фонового эталона обозначено явно.

## Два параметра в JSON модели

Параметры находятся в **сохранённом файле модели** в `Models/SSVEP`, а не в
`NeuroPiano.json` и не в интерфейсе:

```json
"ClassAcceptanceRadiusMultiplier": 1.0,
"BackgroundRejectionLogOddsMargin": 0.5
```

- `ClassAcceptanceRadiusMultiplier`: `1.0` — базовый радиус; больше — шире,
  меньше — уже. Меняется радиус, поэтому квадрат допустимого расстояния
  умножается на квадрат этого параметра. Допускаются положительные конечные значения.
- `BackgroundRejectionLogOddsMargin`: поправка к обученному фоновому порогу.
  `0.0` — сам обученный порог, не отключение фоновой проверки. Положительное
  значение ужесточает проверку, отрицательное смягчает. Начальное значение `0.5`
  требует примерно в 1.65 раза большего отношения плотностей относительно порога.

После редактирования сохраните JSON и заново включите модель через Unuse → Use.
Повторное обучение для изменения этих двух значений не требуется. Остальные
поля файла — обученные статистики; не заменяйте весь JSON приведённым фрагментом.

## Столбики

Softmax и проценты «доверия» удалены. Столбик каждой ноты показывает минимум
запасов до четырёх границ принятия:

- `log(допустимый квадрат расстояния / фактический квадрат расстояния)`;
- разность её LDA-оценки и максимальной оценки других нот;
- разность логарифмов плотностей её образцов и лучшей другой ноты;
- логарифм отношения плотностей цели и фона минус порог и настройка.

Это непосредственно условия решения. Столбик положителен тогда и только тогда,
когда нота принимается. На нулевой границе принято состояние `None`.
Столбики не нормируются друг на друга и не суммируются в 100%.
Нулевая линия — порог. Графическая шкала фиксирована от -2 до +2 с отсечением,
точное значение подписано у каждого столбика. Это запас допуска, не вероятность.

## Проверки реализации

- Собраны все C#-исходники обоих модулей с reference assemblies .NET Framework
  4.8.1, OpenTK 3.3.3 и NAudio 2.3.0. Отсутствующие в архивах `CommonUnits`
  заменены интерфейсными заглушками только в проверке. Заглушки и сборки сюда
  не включены. Полный запуск WinForms/IPC/аудио на Windows здесь не выполнялся.
- На старой калибровке `SSVEPTest1Ign.phs` веса LDA совпали с исходной моделью
  точно; RESS и извлечение признаков сохранены. В этой записи нет класса 1200,
  поэтому её новую модель нельзя использовать для проверки полноценного принятия.
  Нулевой выход такой неполной модели на EEGTestCE.phs не является доказательством
  подавления фона при сохранении целей.
- Независимые синтетические обучение и тест с восемью частотами, периферической
  стимуляцией и шумом: 148/160 правильных целевых окон, 12 None, 0 ошибочных нот,
  обнаружены все 32 целевые пробы; фон — 0/160 принятий.
- После калибровки на независимом широкополосном шуме, при поправке фона 0.5:
  1/320 ложных принятий в тесте. Это имитация воды, не настоящая запись из банки.
- Увеличение радиуса до 1.25 в синтетическом тесте увеличило принятие целей
  до 157/160; изменение параметров монотонно соответствует их смыслу.
- Потоковые перекрывающиеся окна совпали со статическим анализом; None не
  сбрасывает накопление. Проверены JSON, NaN, весь 16-й признак, отображение
  принятия/None и реальная функция отправки событий: первая принятая проба
  сразу даёт Play, None не даёт ни Play, ни Release.
- Контроллер калибровки в обоих режимах даёт 80 целевых и 80 фоновых эпох
  для десяти повторений; порядок нота → фон сохранён, метки парные,
  шесть фоновых позиций сбалансированы, на фоне мерцают все клавиши.

Нулевая частота ошибок на новой живой ЭЭГ не доказана этими проверками.
После новой калибровки нужна отдельная запись применения и отдельные фоновые
тесты. Настройки предназначены для выбора баланса пропусков и ложных нот.

## Режекция ЭОГ

Существующие контролы и их расположение сохранены. Пороги вводятся вручную
в мкВ, отдельно для VEOG и HEOG; соответствующие флажки включают проверки.
Настройки немедленно сохраняются в `PolyHub.json`. В полном потоке actiCHamp
и в PHS значения находятся в вольтах, поэтому при проверке используется
перевод в мкВ (`× 1 000 000`). Каналы находятся по фиксированным выходным
именам HEOG/VEOG, независимо от выбранных исходных физических электродов.

- VEOG: размах `max − min` во всём проверяемом интервале.
- HEOG: максимальный модуль `max(|HEOG|)` во всём интервале. Отдельная база
  фиксации не вычисляется и не требуется. Имя сохранённого JSON-поля
  `HeogFixationDeviationThresholdMicrovolts` оставлено для совместимости настроек.
- Строгое превышение любого включённого порога даёт `Rejected`.
  Отсутствующий включённый ЭОГ-канал или некорректные значения не проходят проверку.

Выбор профиля по-прежнему выбирает настройки для редактирования. Первый
SSVEP-слой использует `Gaze selection`. Калибровка F6 использует `Covert attention`
независимо от выбранного для редактирования профиля; его редактирование не
переключает первый слой. Отдельные режимы, кнопки фиксации и дополнительные кнопки Use не добавлены.

При обучении проверяется **вся эпоха**, включая фон 1200. Отклонённая эпоха
полностью исключается ещё до RESS, затем из LDA и расчёта целевых/фоновых
допусков. В журнале обучения указаны числа принятых и отклонённых эпох каждого
класса. Если весь имеющийся класс отклонён, обучение явно останавливается.
При выключенной режекции прежний алгоритм и результат обучения сохранены.

В реалтайме и при Play записи ЭОГ проверяется в том же окне, что и ЭЭГ.
Отклонённое окно не анализируется классификатором и не отправляет команду ноты
2003. После артефакта обычный ход скользящего окна продолжается. При незагруженной
или несовместимой модели мониторинг ЭОГ работает отдельно: окно 1 с, шаг 250 мс.
Для живого потока должен быть подключён существующий вход SSVEP-процессора;
при воспроизведении подключение исходной записи для ЭОГ обеспечено автоматически.

В TimeSeries и TimeFrequency отклонённый интервал показан приглушёнными цветами
с отдельной подписью `Rejected` под строкой маркеров. Все исходные маркеры
сохраняют свои числовые коды, положения и цвета; режекция их не заменяет
и не приглушает. При просмотре калибровочной записи приглушается вся
отклонённая эпоха; её строка также серая. Analysis показывает `Rejected` с каналом
и измеренным значением. В среднем спектре класса такие эпохи исключены; отдельно
выбранную эпоху можно посмотреть, включая её исходный спектр. Сигнал не удаляется
и не меняется. Изменённый порог заново применяется к статическому просмотру.

### Событие для NeuroPiano

Для нового эпизода артефакта PolyHub отправляет через существующий event-link:

- `Code = UserEvent (1000)`, `State = 0`, `Value0 = 2005`;
- `Value1`: маска `1` — VEOG, `2` — HEOG, `4` — недоступные/некорректные данные;
- `Text = Rejected: ...`, `QpcTimestamp` — конец отклонённого окна.

Перекрывающиеся отклонённые окна одного непрерывного эпизода не дублируют событие.
Обычные команды 2003/2004 сохранены. Новый диагностический маркер также сохраняется
при живой записи в прежнем PHS-формате. State 0 не создаёт дополнительного класса
или эпохи. При чтении метки стабильно упорядочиваются по времени, включая более
поздно записанную диагностику анализа.

**Обработку события в NeuroPiano добавляем следующим изменением:** звук артефакта,
а при калибровке — повтор той же пробы с полными Cue/Settling/Stimulus до получения
нужного числа принятых эпох. В этом архиве исходники NeuroPiano не изменены;
автоматического повторного предъявления в текущем NeuroPiano ещё нет.

### Проверки этого изменения

- Все исходники PolyHub собраны с исходными CommonUnits, .NET Framework 4.8.1
  reference assemblies и OpenTK 3.3.3. Полный запуск на Windows/actiCHamp здесь
  не выполнялся; проверки вычислений и интерфейса выполнялись в Mono/Xvfb.
- На SSVEPCalibIgn.phs сохраняются 28 исходных каналов и 160 исходных эпох;
  в модели и RESS — только 26 ЭЭГ-каналов. При VEOG 150 мкВ исключены 6 целевых
  и 9 фоновых эпох; модель обучена на 74 целевых и 71 фоновой эпохе.

## EEG-only SSVEP training (2026-10-07)

Training excludes the fixed actiCHamp differential outputs `HEOG` and `VEOG`.
These output names are assigned by their EOG roles, regardless of the physical
electrodes chosen for the pairs. The same selector is used by the training UI
and the trainer, so a direct trainer call cannot include either EOG output.
All remaining channels keep their original order.

The full stream, PHS recording, playback, EOG display and NeuroPiano are unchanged.
Existing PHS calibration recordings can be opened and trained again. Model
loading retains its previous behavior. Remove obsolete models and train a new
model from the existing calibration recording.

With rejection disabled, validation used SSVEPCalibIgn.phs: all 160 epochs remained available, the new
model had 26 channels, and replacing only EOG samples in a test copy produced
byte-identical trained model JSON and identical replay features/decisions.
The algorithm equations, model JSON format and EOG rejection settings were not changed.


## Model controls

`Delete` replaces the former memory-only `Clear` button. It is enabled when a
model is selected and training is idle, even if no model is loaded. A Yes/No
confirmation precedes deletion of the selected JSON file. Deleting another
model preserves active control; deleting the active model unloads it, disables
control and sends the existing release command when control was enabled.

Selecting another model displays `Use`; one click replaces the current model
and resets the analysis buffer. For the currently used model, the same button
displays `Unuse` and disables control. Model replacement releases the old model
references automatically; a separate manual unload button is unnecessary.
